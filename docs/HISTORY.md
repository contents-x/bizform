# ビズフォーム公式サイト 変更の経緯

運用ルールは [CONTENT-RULES.md](CONTENT-RULES.md) を正本とし、ここにはルールが生まれた経緯と過去の不具合を日付順に残す。ルールを変えるときは、理由をここへ追記する。

## 2026-09-17

- 配色を全ページ青に統一し、青緑（`#1596A3` など）をやめた。
- ページ別のヘッダー上書き29件・フッター上書き4件を削除し、ヘッダー・フッターを全ページ共通にした。上書きがあると、ページを移るたびにロゴの形やCTAの色が変わっていた。

## 2026-09-20

- 追従ヘッダーを `position: sticky` から `fixed` に変えた。ラッパーの高さがヘッダーと同じ79pxのため、stickyでは79pxスクロールした時点で追従しなくなっていた。

## 2026-09-23

- 手書き風フォント（`Klee`、`Yu Kyokasho` など）をやめて明朝に統一した。片方のOSにしか無く、もう片方では `cursive` に落ちて別物に見えていた。

## 2026-09-26・09-28

- プライバシーポリシー「6. 外部サービスの利用」に、HubSpot と当社CRMへ送る導入相談・資料ダウンロードのフォームを追記した。

## 2026-09-28

- ヘッダーとメニューの「資料を見る」を「資料ダウンロード」に改めた（項目数は変えていない）。
- ヘッダーの各項目が「料／金」のように2行へ折り返す不具合を直した（PCの全幅で起きていた）。
- `.service-page img` のようにページクラスと要素名だけで書いた指定がヘッダー・フッターにも効き、サービス内容・文面サンプル・活用シーンでロゴが4倍に拡大していた。`:where(main)` で本文に限定した。
- TOPの新規開拓の課題セクション（「新規開拓が、日々の業務に埋もれている」）を削除した。
- 導入相談フォームを公開した。共用の HubSpot フォームが部署（`busyo`）を必須にしており、空欄を送っていたため、09-29 の修正までの導入相談は HubSpot に毎回拒否されていた（送信者には「送信できませんでした」と表示）。

## 2026-09-29

- ヘッダーの幅の境目を `max-width: N` と `min-width: N.02px` の組み方に改めた。`max-width: 1040px` と `min-width: 1041px` では、拡大表示やWindowsの表示スケールで生じる 1040.3px のような幅でどちらも当たらず、ヘッダーがはみ出していた。
- 導入相談で部署が空なら `未入力` を送るようにした。
- 失敗の案内のあと送り直すたびに、同じ問い合わせが CRM の受信箱に増えていた（同じ内容が2件届いた）。同じ入力内容の写しは1回だけ送るようにした。
- 追従CTAに「しまう」を追加した。
- TOPを9ブロックから6ブロックに整理した（特徴の4カードを要点の帯へ統合）。キャンペーンの文言を追加し、帯には説明文を載せないと決めた。
- サービスページを9ブロックから6ブロックに整理した。公開直後、キャッシュに残った古い `service.css` と新しいHTMLが組み合わさって表示が崩れたため一度戻し、CSSに `?v=` を付けて公開し直した。
- 料金ページを8ブロックから6ブロックに整理し、比較を表から一覧と横棒グラフに作り直した。
- 導入相談・資料ダウンロードの入力フォームの見た目を BizManga のお問い合わせフォームに合わせた（平澤指示）。資料ダウンロードのページを見出し・1文・フォームだけにした（平澤指示）。

## 2026-09-30

- CSS と JavaScript を整理した。見た目・文言・動作は変えていない（全20ページ×6幅の画面を1画素単位で比較し、すべての要素・画面幅・ホバーやフォーカスの状態で効く指定が同じであることと、メニュー・追従CTA・FAQ・2つのフォームなど54項目の動作が同じであることを確認）。
  - `style.css`（約110KB）を `assets/css/` の共通 `site.css` とページ別の `home.css`・`examples.css`・`use-cases.css` に分け、`service.css`・`pricing.css`・`faq.css` も同じフォルダへ移した。
  - どのページも使っていない旧料金ページ用の `.pricing-*` など86クラス分の指定と、後の指定で必ず上書きされていた宣言（760px の共通指定や、活用シーンの480px以下の指定の大半など）を削除した。
  - サービスと料金で同じ内容が別名で書かれていた帯・見出し・最後のCTAを、共通の `.block-*`・`.final-cta` などにまとめた。TOPの最後のCTAも `.final-cta` を使う（文字を拡大したときの列幅の決まり方が違うため、TOPだけ `1fr` を残した）。
  - `app.js` を全ページ用の `assets/js/site.js` と、フォームのある2ページだけが読む `forms.js` に分けた。
  - CSS・JS の `?v=` を内容のハッシュにし、`scripts/stamp_assets.py` で付けるようにした。
  - 公開前チェック `scripts/check_site.py` を GitHub Actions の公開手順に入れ、失敗したら公開しないようにした。表示崩れの確認 `scripts/layout_check.py` も追加した。
  - 旧ファイル（`assets/style.css`・`app.js`・`service.css`・`pricing.css`・`faq.css`・`faq.js`）は、キャッシュに残った古いページのためだけに残した。次の公開で削除する。

## 2026-10-01

- 続けて、見た目・動作を変えずにできる整理を行った（画面・CSSの効き方・動作の比較で確認）。
  - 旧ファイル6つと、旧CSSだけが使っていた画像 `asset_pricing_hero_bg.webp` を削除した。
  - どの要素にも当たらない指定（`.info-card h3`、`.field legend`、FAQの見出しや活用シーンのヒーローの注記・カードの一部など、HTMLから消えた部品の名残）と、未使用のトークン `--brand-blue-bright`・`--line-soft` を削除した。
  - `site.css` の画面幅別（`max-width`）の指定を条件ごとに1つのブロックにまとめ、ファイル末尾へ移した（PCのヘッダーの `min-width` の指定はヘッダーのそばに残した）。メニューの `body .global-nav > a` のような優先度だけを上げる書き方と、`!important`（ガイド一覧の長い見出し、文面サンプルの矢印）をやめた。
  - 文面サンプルと活用シーンで同じだった幅・帯・ボタンを `.showcase-*` にまとめた。
  - FAQのCSSを他のファイルと同じ1ルール1行の書き方にした。
  - `forms.js` で2か所にあった HubSpot への送信内容の組み立てを1つにし、JavaScriptの各ファイルを関数で包んで名前がファイルの外に出ないようにした。
  - 公開前チェックに、同じ質問のFAQの回答が各ページで一致しているかの確認を加えた。チェック用スクリプトの共通部分を `scripts/site_files.py` にまとめた。
  - GitHub Actions の各アクションを Node.js 24 で動く版に上げた。公開と表示崩れの確認は、Ubuntu 24.04 に固定した（`ubuntu-latest` は 2026-10-19 から順次 Ubuntu 26 に切り替わる。公開前チェックの Python と、Playwright が入れるブラウザの部品を変えないため）。
- 文面サンプルを9ブロックから6ブロックに整理した。「作り方」の説明が3か所（4つの工程・6段階の流れ・確認の4項目）に分かれていたのを「文面ができるまで」1か所にまとめ、架空の管理画面、画面のイラスト4枚、手書き風の飾り文字を外した。ページ独自の青いボタンをやめ、ほかのページと同じ帯・見出し・ボタン・最終導線にした。
  - 文章は元の文を使った。変えたのは、ヒーローの説明（「会社名を変えるだけの一斉送信はしません」を追加）とボタン（「実際の運用フローを見る／サンプル文面を確認する」→「無料で相談する／サンプル文面を見る」）、比較の補足（後半を黄色の強調の説明に差し替え）、工程5「確認して送信」（元の6段階の流れと承認管理の文から作成）、最終導線（根拠を示せない「最適化」を避け「ご相談時にご説明します」に）、「反応」→「返信」、見出しの言い回し、ビズフォームと依頼企業の役割の文、FAQ「文面はすべてAIが自動で作るのですか？」の追加（FAQページと同じ回答）。「作って終わりではない」の見出しと6段階の流れ、確認の4項目の前置き、「数千件でも一社ずつ」の一文は外した。

## 2026-10-07

- TOPのヒーローを作り直した。何を代行するかが数秒で分かるよう、見出しを「客先接触面積の最大化を、最小工数で。」から「調べて、書いて、送る。／新規開拓を、まるごと代行。」に変え、囲みコピーと4工程のビジュアルを加えた（平澤さんの指示）。
  - ビジュアルは、透過のデスク素材＋HTML/CSSのカード・SVGの矢印で一度作ったが、カードの位置が画面幅で変わり（1920pxで矢印とカードがずれた）、見た目も整わなかったため、平澤さんが生成したPC用・スマホ用の完成画像に切り替えた。どちらもカード・パソコン・デスクの部分を切り出してWebPにした（`asset_hero_flow_pc.webp` 1012×650、`asset_hero_flow_sp.webp` 896×770）。カードの文字は画像のため、4工程を `alt` に書いた。透過のデスク素材（`asset_hero_desk.webp`）は使わなくなったので削除した。
  - 1024px以下は画像内の文字が読める大きさを保つため1列にした。スマホではカードの文字が小さい（画像内でカードが小さく描かれているため）。
  - 背景は壁の写真（`asset_hero_wall.webp`）をやめてCSSだけにした。要点の帯はPCでは左の列に入れた。
  - ヘッダー、2か所のキャンペーン表示、ボタンの見た目とリンク先、要点の帯の文言と注記は変えていない。書体・色・ブレークポイントは既存のトークンと 1024px・768px・横向きスマホ（高さ480px以下）だけを使い、新しいものは足していない。
  - 使わなくなった `asset_hero_wall.webp`・`asset_hero_workspace.webp` は削除した（平澤さんの判断。古いページのキャッシュのために残すことはしない）。
  - `<title>` と `description` は旧キャッチコピーのまま残している。ヒーローの見た目が決まってから、SEO の方針と合わせて作り直す（平澤さんの判断）。
