# ビズフォーム公式サイト コンテンツ運用ルール

ルールが生まれた経緯と過去の不具合は [HISTORY.md](HISTORY.md) に日付順で残している。

## サイトの基本方針

トップページで全体像が分かり、料金・サービス内容・文面サンプルへすぐ移動できる構成にする。検索から下層ページへ来た人も、そのページ内で主な疑問を解決できるようにする。

### サービス内容の正本

- ビズフォームは、依頼企業の商材を提案するために、営業先企業の選定・調査・個別文面作成・公開問い合わせフォームへの送信・結果共有を代行する。
- 構成・用語・文言は、営業資料 `Bizform_revised.pdf`（修正スライド）に準拠する。サービスは「初回接点を増やす新規開拓の一括運用サービス」と説明し、業務は「リスト準備・企業調査・文章作成・送信管理・レポート」、役割分担は「ビズフォームがつくる・届ける／営業が商談につなげる」と表す。ただし、このルール文書で禁止・限定している表現（業界最安値の言い切り、開封・到達、確実に届く、架空文面の実例扱いなど）はスライドにあっても転記しない。
- 「フォーム」は営業先企業が公開する問い合わせ窓口を指す。依頼企業の受付フォームの制作・改修、応募受付・面談予約の管理、メール配信ツールの提供として説明しない。
- 業種別の活用例は「依頼企業の商材」「営業先となる法人」「送る提案」を明確にする。人材・採用分野も、求人企業への法人営業として説明する。
- 依頼企業は商材・対象条件を共有し、必要な確認と返信後の対応・商談・提案を担う。「成果を待つだけ」など、この役割を省く表現は使わない。
- 改善対象は営業先の条件、文面、送信運用とする。送信完了・送信不可・エラーを区別し、送信完了を相手の受信・開封と同一視しない。返信は共有された状況をもとに扱い、未確認の開封計測や自動追跡をうたわない。
- 文面サンプルでは、依頼企業・営業先企業・提案商材を架空の設定として明示する。架空の商材に「ビズフォーム」の名称を流用しない。PC・スマホとも同じHTML本文を表示し、画像内に異なるサービス説明を残さない。

似た意味の「ビズフォームとは」「特徴」「選ばれる理由」は独立ページにせず、`/service/` に統合する。

サイト構成は次の9ページ群を正本とする。

1. `/` TOP
2. `/service/` サービス内容
3. `/pricing/` 料金・契約条件
4. `/examples/` 文面・運用サンプル
5. `/use-cases/` 活用シーン
6. `/faq/` よくある質問
7. `/resources/` 資料ダウンロード
8. `/contact/` 導入相談・お問い合わせ
9. `/guide/` フォーム営業ガイドと記事群

ヘッダーは「サービス内容｜料金｜文面サンプル｜活用シーン｜よくある質問｜資料ダウンロード｜無料で相談する｜電話で相談」に固定し、追加しない。

TOPは営業資料の要素を6ブロックに絞り、キャンペーン帯を加えて「ファーストビュー（ヘッダー下のキャンペーンのお知らせ＋ヒーロー＋要点の帯） → キャンペーン帯 → やること（3つの工程と役割分担） → 送る理由（文面サンプル） → 料金プラン → FAQ → 最終導線」の順とする。同じ説明を複数のブロックで繰り返さない。

サービスページの導入の流れは「注文書・契約書の締結 → 初回面談 → 送信リスト・送信内容の整備（約2週間） → 貴社専用PCの準備 → 送信スタート」とし、初期費用は契約時、月額費用は送信スタート後から発生することを併記する。

### 日本語表記と説明文

- 見出しの上に同じ意味の英字ラベルを重ねない。装飾の英文署名も使わない。
- 比較のラベルは「導入前／導入後」、質問・回答のバッジは「問／答」とする。会社名、URL、メールアドレス、本文中のAI・IT・PDFなどの用語は意味に合わせて残す。
- 「出会い」などの抽象表現を使わず、企業調査、文面作成、送信、返信対応、商談など、誰が何を行うかを具体的に書く。
- 全体の送信規模は「月3万〜8万件」、上限だけを示す場合は「月最大8万通」に統一する。プラン別件数や件数の算定条件は確認済みの内容だけを掲載する。

## 配色（全ページ共通）

基調色はサイト全体で1つとする。**ページごとに独自の配色を作らない。**

| 用途 | 色 | トークン |
|---|---|---|
| 濃紺（見出し・ヘッダー・フッター） | `#071E45` | `--brand-navy` |
| 深い濃紺 | `#051734` | `--brand-navy-deep` |
| 青（主アクセント・ロゴ・リンク・塗り） | `#1265E8` | `--brand-blue` |
| 濃い青（ホバー・グラデーション） | `#0D4FB8` | `--brand-blue-dark` |
| 淡い青（セクション背景） | `#EFF5FF` | `--pale-blue` |
| オレンジ（CTAボタン） | `#F5A623` | `--brand-orange` |
| 赤（TOPのキャンペーン帯だけ） | `#D92D20` | `--campaign-red` |

- 正本は `dist/assets/css/site.css` 冒頭の `:root` トークン。**色を足すときはベタ書きせずトークンを追加する。**
- `site.css` とTOP・サービス・料金・文面サンプル・フォームのCSS（`home.css`・`service.css`・`pricing.css`・`examples.css`・`forms.css`）は、16進の色をすべてトークンで指定する（`scripts/check_site.py` が直書きを検出する）。影や半透明の重ねに使う `rgba()` はその場で書いてよい。
  活用シーン・FAQのイラストに合わせた淡い色や影は、各ページのCSSにその場で書いてよい。2か所目で使うことになった色はトークンにする。
- **青は `dist/assets/images/` のイラスト（色相215°前後）に合わせている。**
  画像を差し替える際も、この色相から外さない。外す場合は配色側も併せて見直す。
- `--brand-blue` は白背景の小さい文字でも 5.18:1 でWCAG AAを通るため、文字にも塗りにも同じ値を使う。
- オレンジのCTAボタンの文字色は**濃紺**にする。白文字は 2.03:1 でAAに大きく届かない（濃紺なら 8.09:1）。
- 青緑（`#1596A3` など）は使わない。
- 赤はTOPのキャンペーン表示（ヘッダー下の細い1行のお知らせと、ヒーロー直下の帯）だけに使い、文字は白（4.83:1）にする。CTAボタンやほかの要素へ広げない。

## 書体（全ページ共通）

書体はサイト全体で2種類とする。**ページごとに独自の `font-family` を書かない。**

| 役割 | 書体 | トークン |
|---|---|---|
| ページ見出し（h1）・セクション見出し（h2）・添え書きのキーコピー | 明朝 | `--font-serif` |
| カード見出し・h3以下・ラベル・本文・フォーム・UI | ゴシック | `--font-sans` |
| 装飾数字（`01.` など） | Georgia | `--font-latin` |

- 正本は `dist/assets/css/site.css` 冒頭の `:root` トークン。**書体を足すときはベタ書きせずトークンを追加する。**
- ページ別のCSSは独自の書体を持たず、`site.css` のトークンを参照する。
- ゴシックは `body` に一度だけ指定する。ゴシックにしたい要素へ `--font-sans` を書き足す必要はない。
- **明朝はh1とセクション見出しh2だけに使う。** カード・グリッド内の見出しは、h2であってもゴシックにする
  （`.uc-challenge-grid h2`、`.pr-plan h2`（料金ページのプラン名）、`.info-card h2`、`.form-complete h2`（フォームの完了表示）が該当）。
  明朝は小さい字では線が細って読みにくいため、見出しの階層を書体で分ける。
- Webフォントは読み込まない。**`@font-face`・Google Fontsのリンクを追加しない。**
  表示速度と、第三者への接続を増やさないことを優先する。
- 各スタックは **macOS → Windows → Noto → 総称** の順で揃える。
  順序を逆にすると、Notoを入れている端末だけ他と違う見え方になる。
- 手書き風フォント（`Klee`、`Yu Kyokasho` など）は使わない。
  片方のOSにしか入っておらず、もう片方では `cursive` へ落ちて別物になる。

### 本文の読みやすさ

- 基本の本文サイズはPC18px、768px以下は16px。カードの説明・FAQの質問と回答も原則16px以上とし、主要な導入説明は18px程度にする。
- 小さな補助ラベルやスクロール案内は本文と区別する。説明文を縮めてカードに押し込まず、列数・幅・余白を調整する。
- 明るい背景の本文は `--text-body`（`#1A3355`）、補助文は `--muted`（`#435670`）。濃い背景では `--on-dark` / `--on-dark-muted` を使う。
- 文字を拡大した際は、PC・中間幅・スマホの各指定を確認し、固定高さによる文字欠けや画像との重なりを防ぐ。

## ヘッダー・フッター・ロゴ（全ページ共通）

**マークアップの正本は `dist/assets/js/site.js` の `header` / `footer` テンプレート1箇所のみ。**
全ページがこれを読み込むため、HTMLは元から共通。**見た目をページ側で上書きしない。**

- **ロゴ**: 公式ロゴ（紙飛行機マーク＋「ビズフォーム」）の画像 `dist/assets/images/asset_logo_bizform.webp` を使う。
  元データは `BizForm_F01_Logo.pdf`（中身は1536×1024のPNG）で、白背景を透過して余白を切り落としている。
  SVGや白抜き版を入手したら差し替える。ロゴを文字やCSSで作り直さない。
  - 大きさは高さだけで指定する（`.logo img`）。ヘッダーはPC32px、768px以下28px、389px以下24px、319px以下（折りたたみスマホの外画面）20pxで、
    350px幅でも相談ボタン・電話ボタン・メニューボタンと1行に収める（28pxのままだと361〜389pxではみ出す）。
  - ロゴの青（#0033B3）・金（#CF9B2D）はサイトの配色トークンと別の値だが、ロゴ画像の中だけで使う。
    サイトの配色をロゴに合わせて変えない。
  - 濃紺のフッターではロゴの青が見えないため、白い台紙（`.logo-plate`）に載せる。
  - favicon（`dist/favicon.ico`）と `dist/apple-touch-icon.png` は紙飛行機マークだけを使う。
    全ページの `<head>` で指定し、ページを追加するときも同じ2行を入れる。
- **ヘッダーCTA**（無料で相談する）: **オレンジ**（`.button-primary`）で全ページ共通。
  文字色は濃紺（8.09:1）。「資料ダウンロード」は白地＋青枠（`.button-secondary`）で、`/resources/#download` のフォームへ直接飛ぶ。
- **電話で相談**: 「無料で相談する」の右隣に濃紺（`.button-tel`）で置き、`tel:03-6261-0764` へつなぐ。
  1240px以上は「電話で相談」と番号の2段、1040.02〜1239.98pxと768px以下はアイコンだけ（`aria-label` と `title` に番号）、
  349px以下は幅が足りないため出さない（メニューと追従CTAには残る）。メニュー内では番号付きの横長ボタンにする。
- **ヘッダーの項目は1行で収める**: ナビとボタンの文字は `white-space: nowrap`。日本語は文字の間で改行できるため、
  幅が足りないと「料／金」のように各項目が折り返してしまう。
  1240px以上は余白を詰めて番号付きの電話ボタンまで並べ、1040.02〜1239.98pxは電話をアイコンにし「資料ダウンロード」を「資料DL」と短縮する。
  - ヘッダーの行と追従CTAの文字サイズは px で指定する（ボタンは本文の18pxを継承）。rem だとブラウザの文字サイズ設定
    （「大」＝20px）でナビだけが大きくなり、1280px幅でも電話ボタンが画面外に切れていた。メニューを開いた縦の一覧は rem のままでよい。
  - 幅の境目は `max-width: Npx` と `min-width: N.02px`（または `max-width: N.98px` と `min-width: (N+1)px`）で隙間なく組む。
    `max-width: 1040px` と `min-width: 1041px` の組み合わせだと、拡大表示やWindowsの表示スケールで生じる 1040.3px のような幅で
    どちらも当たらず、ヘッダーがはみ出す。
  - それでも収まらない端末（書体・スクロールバー・文字の拡大設定の違い）に備え、`site.js` の `fitHeader` が行の右端を実測し、
    はみ出すときは `html.header-compact`（短い表記とアイコンの電話）、なお収まらなければ `html.header-no-tel`（ヘッダーの電話を隠す）を付ける。
    CSSの境目で収まるように作り、この仕組みは保険として扱う。スクロールバーの無いスマホやPCの標準設定で `header-compact` が付く幅は作らない
    （今はスクロールバーのあるPCの350px前後だけで付く）。
  - ヘッダーに文字を足したら、「スマートフォンの表示・操作」にある表示の確認の条件で、はみ出し・折り返しが無いことを確認する。
- **追従ヘッダー**: `.site-header` は `position: fixed` で全ページ追従する。
  ラッパーの `[data-site-header]` が `--header-height` ぶんの高さを確保して
  本文の重なりを防ぐ。この高さは `site.js` が実測して設定するので、
  **ヘッダーの高さを変えてもCSSの数値を直す必要はない**。
  ⚠️ `position: sticky` に戻さない。ラッパーの高さがヘッダーと同じ(79px)ため、
  stickyだと79pxスクロールした時点で流れて**追従しなくなる**。
- **フッター**: 背景は `--brand-navy-darkest`。ページごとに変えない。
- **ページ単位の要素指定**: `.service-page img` のようにページクラスと要素名だけで書く指定は、ヘッダー・フッターにも効く。
  ページ内だけに効かせるときは `.service-page :where(main) img` のように本文へ限定する（`:where()` で優先度は元のまま）。
- **禁止**: `.home-page .site-header` のような**ページ別の上書きを足さない**。
  上書きがあると、ページ遷移のたびにロゴの形やCTAの色が変わる状態に戻る。
- 変更は必ず全ページに波及するため、`/`・`/service/`・`/faq/` の3ページで
  PC（1440px）とスマホ（390px・メニュー開閉）を確認する。

## 追従CTA（フローティングバー）

`site.js` が `.floating-cta` を生成し、**お問い合わせページ以外の全ページ**に出す。

- **導線**: 「資料ダウンロード」（白地＋枠。`/resources/#download`）、「無料で相談する」（青／`--brand-blue`）、「電話で相談」（濃紺）の3つ。
  ヘッダーCTAのオレンジと色を分け、画面下で主張しすぎないようにしている。
- **出す条件**: `max(画面高の60%, 420px)` を超えてスクロールしたら出る。
  ヒーローのCTAが見えている間は出さない（同じ導線を二重に見せないため）。
- **お問い合わせページでは出さない**。目の前のフォームと競合するため。
  判定は `site.js` の `isPage('/contact/')`（ページのパスが `/contact/` と一致するか）で行う。存在しないURLで出る404ページは、`/contact/` で始まっていても導入相談ページとみなさない。
- フッターの最下部リンクが隠れないよう、`body.has-floating-cta .site-footer` に
  バーの実測高に連動する下余白を確保している。
- `site.js` がヘッダーとバーの実測高をルートのCSS変数へ反映し、スクロール余白にも使う。
  Tab・Shift+Tabで選択中のリンクやFAQが固定要素に隠れる場合だけ、表示位置を補正する。
  固定ヘッダー内・CTA内の操作と、モバイルメニューのフォーカス制御は補正対象にしない。
- スマホ（768px以下）では「資料DL」「無料相談」と短縮して残りの横幅を等分し、電話は「電話」と短縮した幅固定のボタンにする。長い表記と短い表記はどちらも `site.js` が出力し、CSS（`.floating-cta-label-long`／`-short`）で切り替える。
  374px以下は「資料DL」「無料相談」のアイコンを外して3つを1行に収める。PCの電話ボタンは番号まで表示する。
- **しまう（最小化）**: バーの右上のタブ「しまう」で、バーを画面の下へ引っ込められる。
  しまうと画面の下端に青いタブ「お問い合わせ」だけが残り、押すとバーが戻る。
  しまった状態は `sessionStorage` に記録し、同じ訪問（ブラウザのタブを閉じるまで）ではページを移ってもしまったままにする。次の訪問では開いた状態から始める。
  ストレージが使えない環境でも、そのページの中では開閉できる。しまっている間のリンクは `visibility: hidden` でキーボード操作の対象から外す。
  バーの高さの変数（`--floating-cta-height`）は、タブを含めた開いた状態の高さを常に確保する。

## TOPデザイン

- PCは1440px前後を基準にし、共通コンテンツ幅は最大1180pxとする。
- 見出しの書体は「書体（全ページ共通）」に従う。TOPだけ別の書体指定を作らない。
- TOPで使う写真・人物イラストの正本は `dist/assets/images/` に置く。見出し、説明、数値、ボタンなど判断に必要な情報は画像に含めずHTMLで表示する。
- 主要画像には固有の `alt`、`width`、`height` を指定し、ファーストビュー以外は遅延読み込みにする。
- 背景は白と薄い青（`--pale-blue`）を交互に使い、濃い色は最終導線だけにする。写真の背景はヒーローだけ。ボタンはサイト共通の `.button-primary`（オレンジ）と `.button-secondary` を使い、TOPだけの色のボタンを作らない。縦書きコピーは使わない。
- 3つの工程（企業調査／文面作成／送信・レポート）は各1〜2行で、1024px以下でも3列、768px以下では1列にする。スマートフォンではCTAを横幅いっぱいにする。
- ファーストビューは、囲みコピー「新規開拓の実務を、もっと軽く。」、見出し（h1）「調べて、書いて、送る。／新規開拓を、まるごと代行。」、説明「企業調査・個別文面の作成から、／問い合わせフォームへの送信・レポートまで。／新規開拓の実務を一気通貫で代行します。」、ボタン「無料で相談する」「資料ダウンロード」の2つとする。
  - 目立つ順は h1 → 無料相談ボタン → 囲みコピー → 説明 → 要点 → 注記。明朝は h1 だけで、囲みコピーは小さな青字の枠、説明は通常の太さの `--text-body`、注記は `--muted` にし、囲みコピーを h1 より目立たせない。
  - PC（1025px以上）は左にコピー・ボタン・要点（横3列）・注記、右にビジュアルの2列。1024px以下は「コピー → ビジュアル → 要点 → 注記」の1列で、768px以下はボタンを縦に並べ、要点を縦3枚にする。スマホの文字サイズはPCを縮めずスマホ用に指定する。

- 電話相談は `03-6261-0764`（ビズマンガと同じ番号）。導入相談ページ、共通ヘッダー、メニュー、追従CTAに `tel:` リンクで表示する。番号は `site.js` の `TEL` と導入相談ページの2か所で管理する（`check_site.py` の `TEL` と食い違う `tel:` リンクは公開前チェックで止まる）。

  - 受付完了と失敗の判定は HubSpot の応答だけで行う。CRM へは埋め込みスクリプトの `BizcarteInbound.sendForm(form)` で写しを送るだけで、失敗しても画面にも HubSpot 送信にも影響させない（既存の問い合わせ受付を壊さないため）。
  - 成功したらフォームを隠し、受付完了と次の流れ（`[data-contact-complete]`）を表示する。
  - 失敗の案内は2種類に分ける。**HubSpot が 4xx を返したとき**（入力の検証で拒否＝届いていない）だけ、入力内容の確認と再送を促す。**通信断・時間切れ・5xx**（届いたか分からない）では「もう一度お試しください」と書かない。応答が取れなかっただけで届いている場合があり、再送で重複するため。どちらも `office@contentsx.jp` へのメールを案内する。
  - 完了・失敗の文言はHTMLに固定で置き、入力値を画面へ差し込まない。
  - **共用の HubSpot フォームは部署（`busyo`）が必須**で、空欄も拒否される。ビズフォームは部署を任意にしているため、空なら `未入力` を送る。HubSpot に送る項目を変えるときは、必須項目の一覧を確認する。
  - HubSpot が拒否したときは、拒否された項目名（エラー本文の `errors[].message`）をコンソールに出す。入力値は出さない。
  - 二重送信はボタンの無効化だけでなく、フォーム単位の送信中フラグで止める（Enterキーや `requestSubmit()` はボタンを経由しない）。
  - **CRM への写しは、同じ入力内容につき1回だけ送る**（失敗の案内のあと送り直すたびに、受信箱へ同じ問い合わせが増えないように）。内容を直して送り直した場合は別の内容として送る。HubSpot に拒否されても CRM には1件残るようにしてある（部署の必須エラーの間も問い合わせを拾えていた）。
  - ハニーポット `#bfWebsite`（`name="website"`・`tabindex="-1"`）は画面外に置く。`display:none` にしない。値が入っていたら HubSpot へ送らず、画面には受付完了を出す（CRM の埋め込みスクリプトがこの形を自動で認識し、CRM 側で黙って捨てる）。
  - 入力の上限（会社名・氏名200字、詳しい内容5000字）は CRM 側の受付上限（会社名・氏名200字、本文10000字）より小さくしてある。
- **入力フォームの見た目は BizManga のお問い合わせフォーム（https://bizmanga.contentsx.jp/contact）に倣う**（2026-09-29 平澤指示。導入相談・資料ダウンロード共通）。
  - 箱（枠・影・背景）で囲まず、幅640pxの1列に置く（`form.form-card` と `.narrow.form-shell`）。送信後の完了表示だけは箱のまま残す。

## 資料ダウンロード

- 場所は `/resources/#download`（`dist/resources/index.html`）。**ページは見出し「サービス資料ダウンロード」・「入力するとその場でダウンロードできる」の1文・フォームだけにする**（2026-09-29 平澤指示。資料の中身の説明、Webで読む導線、検討項目、相談CTAなどは載せない）。`#download` はページ上部の見出しの帯（`section`）に付けてあり、各所のボタンから来た人にも1文が見える。ヘッダー・メニュー・追従CTA・フッター・各ページ末尾のCTAの「資料ダウンロード」はすべてここへ飛ぶ。トップのヒーローのCTAは「無料で相談する」「資料ダウンロード」の2つ。
- PDFの正本は `dist/assets/docs/bizform-service-guide-202609.pdf`（営業資料 0926 版・29ページ）。元の49.3MBを、macOS標準のQuartzフィルタ（JPEG品質0.6）で画像を圧縮し、元からJPEGだった4枚は元のJPEGのまま戻して約11MBにした。見た目は全ページを画像にして元と比べて確認済み。資料を差し替えるときも10MB前後を目安にし、50MBを超えるファイルはコミットしない。
- **PDFへの直接リンクを、ナビ・本文などフォームを通らない場所に置かない**。PDFの場所はフォームの `data-download-url` にだけ書き、完了表示の「こちらからダウンロード」は送信後に `forms.js` がリンク先を入れる。`robots.txt` で `/assets/docs/` をクロール対象から外している。静的ファイルなので、URLを知っている人は直接開ける（強い保護ではない）。
- 項目は会社名・お名前・メールアドレス（必須）、部署名・電話番号（任意）、プライバシーポリシーへの同意（必須）。**問い合わせ内容の欄は作らない**。ハニーポット `#bfDlWebsite` は導入相談と同じ形。
- `forms.js` は入力チェックを通ったら、HubSpot へ写し → CRM へ写し（`BizcarteInbound.sendForm(form)`。フォームの `data-crm-form="download"` と `data-crm-document` で受信箱の「資料DL」の箱に入る）→ ダウンロード開始、の順に実行し、**どの応答も待たない**。HubSpot や CRM が落ちていてもダウンロードは止まらない。
- HubSpot へは導入相談と同じフォームに送り、本文欄（`message`）に「【資料ダウンロード】資料名」と電話番号を入れて資料DLだと分かるようにする。HubSpot は廃止予定のため、失敗してもコンソールに警告を出すだけにしている。
- 資料を差し替えたら、`data-crm-document` の資料名、ページの説明（容量）、この節を同時に直す。

## CSS・JavaScriptの構成

- CSSは `dist/assets/css/`、JavaScriptは `dist/assets/js/` に置く。
  - `site.css`: 全ページ共通（トークン、基本要素、ヘッダー、ボタン、共通部品、ガイド記事、フッター、追従CTA）。ページ固有の指定は書かない。ただし専用のCSSを持たないページ（ガイド一覧・運営会社・送信方針・停止窓口・404）の少しの指定はここに置く。
    部品ごとの基本の指定を先に書き、画面幅別（`max-width`）の指定はファイル末尾に幅の広い順（1040px → 1024px → 768px → 狭い画面の個別調整）で、条件ごとに1つのブロックへまとめる。PCのヘッダーの幅の範囲（`min-width`）だけはヘッダーの指定のそばに置く。
  - ページ別: `home.css`（TOP）、`service.css`、`pricing.css`、`examples.css`、`use-cases.css`、`faq.css`、`forms.css`（導入相談と資料ダウンロードの2ページ。`forms.js` と同じ）。`site.css` の後に読み込む。
  - `site.js`: 全ページ（ヘッダー・フッター、追従CTA、フォーカス位置の補正、メニュー、横スクロールの案内、表示演出）。
  - `forms.js`: 導入相談と資料ダウンロードの2ページだけ。`site.js` の後、CRMの埋め込みスクリプトと一緒に読み込む。
  - `faq.js`: FAQページの開閉。
  - スクリプトは通常の `<script>` で、ファイル全体を `(() => { ... })();` で包む。包まないと名前がほかのファイルと共有され、同じ名前があると後のファイルが止まる（`check_site.py` が包み忘れを検出する）。
- 共通部品。同じ見た目をページ別に作り直さず、これを使う。
  - `.block`（白の帯）・`.block-blue`（薄い青の帯）・`.block-inner`（幅1120px）・`.block-title`（明朝の見出し）・`.block-lead`（見出しの下の説明）: サービス・料金・文面サンプルの帯と見出し。`.block-note`（小さな注記）は料金・文面サンプル（サービスの注記 `.sv-note` は上下の余白が違うため別のまま）。
  - `.hero-title`（明るい背景のヒーローの見出し）: サービス・料金・文面サンプル。`.hero-buttons`（その下の角の丸いボタン2つ）: サービス・文面サンプル。
  - `.step-cards`（番号付きの工程を横に並べたカード。1024px以下は3列、スマホは縦の一覧）: サービス・文面サンプル。
  - `.highlight`（文面サンプルの黄色の強調）: TOP・文面サンプル。
  - `.final-cta`（濃紺のカード）・`.final-cta-actions`: TOP・サービス・料金・文面サンプルの最後の導線。カードを囲む帯は `.final-cta-block`（TOPは `.section-sm`）。TOPは `.home-cta` を足して、横並びの列幅・説明の幅・スマホの見出しの大きさだけを変えている。
  - `.pending`（「架空サンプル」などの小さなラベル。いまはTOPの文面サンプルだけが使う）。
  - `.breadcrumbs-light`（明るい背景のヒーローのパンくず）、`.step-number`（01・02 の工程番号）、`.more-links`（ブロック末尾の関連ページへのリンク）。
- 読み上げ。見た目だけの記号や番号は読み上げさせない。
  - パンくずは `<nav class="breadcrumbs" aria-label="パンくず">` とし、区切りの「›」に `aria-hidden="true"`、最後の項目（今のページ）に `aria-current="page"` を付ける。
  - CSSの `content` で描く記号（→・✓・+・−・↓・!）は `content: "→"; content: "→" / "";` と書き、`/` の後の代替テキストを空にする（先の宣言は代替テキストの書き方に対応しないブラウザ向け）。
  - 見出しや順番のそばの飾りの番号（01・02）には `aria-hidden="true"` を付ける。目次の `nav` には `aria-label="目次"` を付ける。
- **CSS・JSを変えたら `python scripts/stamp_assets.py` を実行する。** HTMLの `?v=` を内容のハッシュに書き換える。GitHub Pages はHTML・CSS・JSをそれぞれ10分キャッシュするため、`?v=` が変わらないと新しいHTMLと古いCSSが組み合わさって崩れる。
- CSS・JSのファイルの名前や置き場所を変えるときは、古いファイルを1回の公開のあいだ残し、次の公開（10分以上あとの）で削除する。キャッシュに残った古いページが古いファイルを読みに来るため。
  指定を別のファイルへ移すときも同じで、移す前の指定を古いページが読むファイル（`site.css` など）に1回の公開のあいだ残す。`?v=` は新しいページを古いCSSから守るだけで、古いページが新しい `site.css` を読むのは防げない（GitHub Pages は `?v=` を見ずに今のファイルを返す）。
  逆向きも同じで、変えたファイルが、ほかのファイルの新しい版にしか無いもの（トークン、クラス、JavaScript と CSS の取り決め）に頼るときは、1回の公開のあいだ古い版と組み合わさっても崩れないようにしておく。キャッシュの期限はファイルごとにずれる（配信元が付ける経過時間が違う）ため、古いページが新しいファイルと古いファイルを混ぜて読むことがある。
  次の公開で消すものには「Kept for one deploy」のコメントを付ける。いまは `site.css` のフォームと文面サンプルの指定（768px以下の行を含む）、`site.js` の追従バーの表記の切り替え（`matchMedia`）、`use-cases.css` の色トークンの予備の値。
- 画面幅の境目は次のものだけを使い、新しい境目を増やさない。
  1240px・1040.02〜1239.98px（PCのヘッダー）、1040px（メニューの切替）、1024px（タブレット）、900px（活用シーンの業種カード）、768px（スマホ）、
  420px・390px・389px・374px・360px・359px・349px・319px（狭い画面の個別調整）、高さ480px以下の横向き。
  FAQページだけは760pxでレイアウトを切り替える（761〜768pxはPC寄りの配置のまま）。

  確認するもの: HTMLの整形（閉じタグの崩れはページ名を出し、残りのチェックも続ける）、`?v=` の更新漏れ、内部リンクとページ内リンク（`site.js` のヘッダー・フッター・ロゴ・追従バー、資料のPDF、CSSの `url()` と `@import` を含む。空のリンクも止める。大文字と小文字は GitHub Pages と同じく区別する）、画像の `alt`・`width`・`height`、`sitemap.xml` と `canonical`、色トークン、
  料金（プラン名の近くに書いた件数・月額・1件あたり単価と初期費用、「月3万〜8万件」「3万件・5万件・8万件」のような万の表記。ガイド記事と、ほかの会社の名前が同じ文にある件数は除く）、複数のページに同じ文言で載っているFAQの質問の回答がFAQページと一致するか（言い回しの違う質問は比べない）、電話番号（`site.js` の `TEL` を含む）とメールアドレス、
  各ページが読み込むスクリプトと `forms.css`、スクリプトが関数で包まれているかと構文（Node.js がある環境だけ。GitHub Actions では必ず確認する）。どれかの確認が途中で止まっても、それまでに見つかった問題を出して失敗にする。
  どこからも使われていない画像は `NOTE` として表示する（公開は止めない。名前を変えた・使わなくなった画像は、キャッシュに残った古いページのため1回の公開のあいだ残し、次の公開で削除する）。

## ソースの整形・整理

- 文字コードはUTF-8、改行はLF、HTML・CSS・JavaScriptのインデントはスペース2つとする。設定は `.editorconfig` を参照する。
- HTMLはセクション・カード・フォーム項目などの単位で改行する。日本語本文、インライン要素の前後の空白、意図した `br`、属性、要素の順序は維持する。
- HTML整形は `python scripts/format_html.py`、整形済みかの確認は `python scripts/format_html.py --check` で行う。整形と表示・文言の変更は分けてレビューする。
- CSSを削除するときはHTMLだけでなく、JavaScriptが生成する要素や操作後の状態も確認する。`:not()` 内で参照するクラスがなくても、そのルール自体は使用中の場合がある。
- 後の指定で必ず上書きされる宣言（同じセレクター・同じか広いメディア条件）は残さない。どの値が効いているか読み違える原因になる。
- CSSの整理ではブラウザ向けのフォールバック宣言を保ち、PC・スマホ・切替境界の表示とメニュー・FAQ・フォームの操作を確認する。
