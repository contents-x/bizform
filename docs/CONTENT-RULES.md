# ビズフォーム公式サイト コンテンツ運用ルール

## サイトの基本方針

トップページで全体像が分かり、料金・サービス内容・文面サンプルへすぐ移動できる構成にする。検索から下層ページへ来た人も、そのページ内で主な疑問を解決できるようにする。

似た意味の「ビズフォームとは」「特徴」「選ばれる理由」は独立ページにせず、`/service/` に統合する。

サイト構成は次の9ページ群を正本とする。

1. `/` TOP
2. `/service/` サービス内容
3. `/pricing/` 料金・契約条件
4. `/examples/` 文面・運用サンプル
5. `/use-cases/` 活用シーン
6. `/faq/` よくある質問
7. `/resources/` サービス資料
8. `/contact/` 導入相談・お問い合わせ
9. `/guide/` フォーム営業ガイドと記事群

ヘッダーは「サービス内容｜料金｜文面サンプル｜活用シーン｜よくある質問｜資料を見る｜無料で相談する」に固定し、追加しない。

TOPのセクション順は「何のサービスか → 4つの対応工程 → ビズフォームと営業の役割分担 → 送信規模 → 料金・品質・相性の判断導線 → 文面サンプル → FAQ → 最終導線」とする。

## TOPデザイン

- PCは1440px前後を基準にし、本文コンテンツ幅は最大1200px、役割分担セクションは最大1120pxとする。
- 基調色は濃紺 `#063A52`、深い濃紺 `#033247`、青緑 `#1596A3`、淡い青緑 `#EAF7F8`、淡い青 `#F6FBFD`、オレンジ `#F5A623` とする。
- ファーストビューの見出しのみ明朝体、それ以外はゴシック体を基本とする。
- TOPで使う写真・人物イラストの正本は `dist/assets/images/` に置く。見出し、説明、数値、ボタンなど判断に必要な情報は画像に含めずHTMLで表示する。
- 主要画像には固有の `alt`、`width`、`height` を指定し、ファーストビュー以外は遅延読み込みにする。
- 1024px以下でサービス工程を2列にし、768px以下では各セクションを1列にする。スマートフォンではCTAを横幅いっぱいにし、縦書きコピーは非表示にする。

## 料金・契約条件

- 初期費用、月額、含まれる業務、追加費用、送信件数の定義、最低契約期間、変更・解約条件をセットで掲載する。
- 旧資料の金額や件数を、最新条件の確認なしに転記しない。
- `dist/pricing/index.html` の「最終確認中」は、サービス責任者が承認した条件が揃ってから差し替える。
- 対象企業数、送信試行数、送信完了数を混同しない。
- 料金ページは「Heroの3プラン概要 → 全プラン共通業務 → プラン比較 → 適合プラン → 他手法比較 → 特急便 → FAQ → 相談導線」の順を正本とする。
- 料金ページのコンテンツ幅は基本1080〜1120pxとし、比較表を除いてPCでも横へ広げすぎない。
- ライト、スタンダード、プレミアムの人物素材と特急便素材は `dist/assets/images/asset_plan_*.png` と `asset_express_runner.png` を正本とする。

## サンプル・実績

- 架空の文面は必ず「架空サンプル」と表示する。
- 実際の運用例を「実例」として掲載する場合は、社名・文面・結果それぞれの掲載許可を確認する。
- 実績と試算、目標、シミュレーションを同じ数字として扱わない。

## 問い合わせと停止窓口

- 導入相談と、営業案内を受け取った企業からの送信停止依頼は別窓口にする。
- 現在の導入相談フォームは、メールアプリを開く方式。将来フォーム基盤へ接続するときは、送信後の受付完了と次の流れを表示する。
- 停止依頼の処理期限と社内責任者は、正式公開前に決める。

## ページ追加時

- メインメニューは増やし続けず、営業ガイドまたはフッターへ追加する。
- 新しい公開URLを追加したら `dist/sitemap.xml` も更新する。
- 業種名・地域名だけを変えた類似ページは作らない。固有情報や実例を十分に出せる場合のみ追加する。
- 重要な見出し、料金、説明、ボタンは画像内の文字にせずHTMLテキストで実装する。
