# ビズフォーム公式サイト コンテンツ運用ルール

## サイトの基本方針

トップページで全体像が分かり、料金・サービス内容・文面サンプルへすぐ移動できる構成にする。検索から下層ページへ来た人も、そのページ内で主な疑問を解決できるようにする。

### サービス内容の正本

- ビズフォームは、依頼企業の商材を提案するために、営業先企業の選定・調査・個別文面作成・公開問い合わせフォームへの送信・結果共有を代行する。
- 構成・用語・文言は、営業資料 `Bizform_revised.pdf`（修正スライド）に準拠する。サービスは「初回接点を増やす新規開拓の一括運用サービス」と説明し、業務は「リスト準備・企業調査・文章作成・送信管理・レポート」、役割分担は「ビズフォームがつくる・届ける／営業が商談につなげる」と表す。ただし、このルール文書で禁止・限定している表現（業界最安値の言い切り、開封・到達、確実に届く、架空文面の実例扱いなど）はスライドにあっても転記しない。
- 「フォーム」は営業先企業が公開する問い合わせ窓口を指す。依頼企業の受付フォームの制作・改修、応募受付・面談予約の管理、メール配信ツールの提供として説明しない。
- 業種別の活用例は「依頼企業の商材」「営業先となる法人」「送る提案」を明確にする。人材・採用分野も、求人企業への法人営業として説明する。
- 依頼企業は商材・対象条件を共有し、必要な確認と返信後の対応・商談・提案を担う。「成果を待つだけ」など、この役割を省く表現は使わない。
- 改善対象は営業先の条件、文面、送信運用とする。送信完了・送信不可・エラーを区別し、送信完了を相手の受信・開封と同一視しない。返信は共有された状況をもとに扱い、未確認の開封計測や自動追跡をうたわない。
- 文面サンプルでは、依頼企業・営業先企業・提案商材を架空の設定として明示する。架空の商材に「ビズフォーム」の名称を流用しない。PC・スマホとも同じHTML本文を表示し、画像内に異なるサービス説明を残さない。

似た意味の「ビズフォームとは」「特徴」「選ばれる理由」は独立ページにせず、`/service/` に統合する。

サイト構成は次の9ページ群を正本とする。

1. `/` TOP
2. `/service/` サービス内容
3. `/pricing/` 料金・契約条件
4. `/examples/` 文面・運用サンプル
5. `/use-cases/` 活用シーン
6. `/faq/` よくある質問
7. `/resources/` サービス資料・資料ダウンロード
8. `/contact/` 導入相談・お問い合わせ
9. `/guide/` フォーム営業ガイドと記事群

ヘッダーは「サービス内容｜料金｜文面サンプル｜活用シーン｜よくある質問｜資料ダウンロード｜無料で相談する｜電話で相談」に固定し、追加しない。「資料ダウンロード」は2026-09-28に「資料を見る」から改めた（項目は増やしていない）。

TOPのセクション順は、修正スライドに合わせて「ファーストビュー → キャンペーン帯 → ビズフォームの特徴（4つ） → 3つの工程 → 送る理由（文面サンプル） → 返信後の引き継ぎ（役割分担） → 料金・文面・活用シーンの判断導線 → FAQ → 最終導線」とする。

サービスページの導入の流れは「注文書・契約書の締結 → 初回面談 → 送信リスト・送信内容の整備（約2週間） → 貴社専用PCの準備 → 送信スタート」とし、初期費用は契約時、月額費用は送信スタート後から発生することを併記する。

### 日本語表記と説明文

- 見出しの上に同じ意味の英字ラベルを重ねない。装飾の英文署名も使わない。
- 比較のラベルは「導入前／導入後」、質問・回答のバッジは「問／答」とする。会社名、URL、メールアドレス、本文中のAI・IT・PDFなどの用語は意味に合わせて残す。
- 「出会い」などの抽象表現を使わず、企業調査、文面作成、送信、返信対応、商談など、誰が何を行うかを具体的に書く。
- 全体の送信規模は「月3万〜8万件」、上限だけを示す場合は「月最大8万通」に統一する。プラン別件数や件数の算定条件は確認済みの内容だけを掲載する。

## 配色（全ページ共通）

基調色はサイト全体で1つとする。**ページごとに独自の配色を作らない。**

| 用途 | 色 | トークン |
|---|---|---|
| 濃紺（見出し・ヘッダー・フッター） | `#071E45` | `--brand-navy` |
| 深い濃紺 | `#051734` | `--brand-navy-deep` |
| 青（主アクセント・ロゴ・リンク・塗り） | `#1265E8` | `--brand-blue` |
| 濃い青（ホバー・グラデーション） | `#0D4FB8` | `--brand-blue-dark` |
| 明るい青（ハイライト） | `#3185F6` | `--brand-blue-bright` |
| 淡い青（セクション背景） | `#EFF5FF` | `--pale-blue` |
| オレンジ（CTAボタン） | `#F5A623` | `--brand-orange` |
| 赤（TOPのキャンペーン帯だけ） | `#D92D20` | `--campaign-red` |

- 正本は `dist/assets/style.css` 冒頭の `:root` トークン。**色を足すときはベタ書きせずトークンを追加する。**
- `service.css` は独自の配色を持たず、`style.css` のトークンを参照する。
- **青は `dist/assets/images/` のイラスト（色相215°前後）に合わせている。**
  画像を差し替える際も、この色相から外さない。外す場合は配色側も併せて見直す。
- `--brand-blue` は白背景の小さい文字でも 5.18:1 でWCAG AAを通るため、文字にも塗りにも同じ値を使う。
- オレンジのCTAボタンの文字色は**濃紺**にする。白文字は 2.03:1 でAAに大きく届かない（濃紺なら 8.09:1）。
- 青緑（`#1596A3` など）は使わない。2026-09-17に全ページ青へ統一済み。
- 赤はTOPのキャンペーン帯だけに使い、文字は白（4.83:1）にする。CTAボタンやほかの要素へ広げない。

## 書体（全ページ共通）

書体はサイト全体で2種類とする。**ページごとに独自の `font-family` を書かない。**

| 役割 | 書体 | トークン |
|---|---|---|
| ページ見出し（h1）・セクション見出し（h2）・添え書きのキーコピー | 明朝 | `--font-serif` |
| カード見出し・h3以下・ラベル・本文・フォーム・UI | ゴシック | `--font-sans` |
| 装飾数字（`01.` など） | Georgia | `--font-latin` |

- 正本は `dist/assets/style.css` 冒頭の `:root` トークン。**書体を足すときはベタ書きせずトークンを追加する。**
- `service.css` と `faq.css` は独自の書体を持たず、`style.css` のトークンを参照する。
- ゴシックは `body` に一度だけ指定する。ゴシックにしたい要素へ `--font-sans` を書き足す必要はない。
- **明朝はh1とセクション見出しh2だけに使う。** カード・グリッド内の見出しは、h2であってもゴシックにする
  （`.uc-challenge-grid h2`、`.pricing-hero-plan h2`、`.resource-card h2`、`.info-card h2` が該当）。
  明朝は小さい字では線が細って読みにくいため、見出しの階層を書体で分ける。
- Webフォントは読み込まない。**`@font-face`・Google Fontsのリンクを追加しない。**
  表示速度と、第三者への接続を増やさないことを優先する。
- 各スタックは **macOS → Windows → Noto → 総称** の順で揃える。
  順序を逆にすると、Notoを入れている端末だけ他と違う見え方になる。
- 手書き風フォント（`Klee`、`Yu Kyokasho` など）は使わない。
  片方のOSにしか入っておらず、もう片方では `cursive` へ落ちて別物になる。2026-09-23に明朝へ統一済み。

### 本文の読みやすさ

- 基本の本文サイズはPC18px、768px以下は16px。カードの説明・FAQの質問と回答も原則16px以上とし、主要な導入説明は18px程度にする。
- 小さな補助ラベルやスクロール案内は本文と区別する。説明文を縮めてカードに押し込まず、列数・幅・余白を調整する。
- 明るい背景の本文は `--text-body`（`#1A3355`）、補助文は `--muted`（`#435670`）。濃い背景では `--on-dark` / `--on-dark-muted` を使う。
- 文字を拡大した際は、PC・中間幅・スマホの各指定を確認し、固定高さによる文字欠けや画像との重なりを防ぐ。

## ヘッダー・フッター・ロゴ（全ページ共通）

**マークアップの正本は `dist/assets/app.js` の `header` / `footer` テンプレート1箇所のみ。**
全ページがこれを読み込むため、HTMLは元から共通。**見た目をページ側で上書きしない。**

- **ロゴ**: 公式ロゴ（紙飛行機マーク＋「ビズフォーム」）の画像 `dist/assets/images/asset_logo_bizform.webp` を使う。
  元データは `BizForm_F01_Logo.pdf`（中身は1536×1024のPNG）で、白背景を透過して余白を切り落としている。
  SVGや白抜き版を入手したら差し替える。ロゴを文字やCSSで作り直さない。
  - 大きさは高さだけで指定する（`.logo img`）。ヘッダーはPC32px、768px以下28px、360px以下24pxで、
    360px幅でも相談ボタン・電話ボタン・メニューボタンと1行に収める。
  - ロゴの青（#0033B3）・金（#CF9B2D）はサイトの配色トークンと別の値だが、ロゴ画像の中だけで使う。
    サイトの配色をロゴに合わせて変えない。
  - 濃紺のフッターではロゴの青が見えないため、白い台紙（`.logo-plate`）に載せる。
  - favicon（`dist/favicon.ico`）と `dist/apple-touch-icon.png` は紙飛行機マークだけを使う。
    全ページの `<head>` で指定し、ページを追加するときも同じ2行を入れる。
- **ヘッダーCTA**（無料で相談する）: **オレンジ**（`.button-primary`）で全ページ共通。
  文字色は濃紺（8.09:1）。「資料ダウンロード」は白地＋青枠（`.button-secondary`）で、`/resources/#download` のフォームへ直接飛ぶ。
- **電話で相談**: 「無料で相談する」の右隣に濃紺（`.button-tel`）で置き、`tel:03-6261-0764` へつなぐ。
  1240px以上は「電話で相談」と番号の2段、1041〜1239pxと768px以下はアイコンだけ（`aria-label` と `title` に番号）、
  349px以下は幅が足りないため出さない（メニューと追従CTAには残る）。メニュー内では番号付きの横長ボタンにする。
- **ヘッダーの項目は1行で収める**: ナビとボタンの文字は `white-space: nowrap`。日本語は文字の間で改行できるため、
  幅が足りないと「料／金」のように各項目が折り返してしまう（2026-09-28 まで PC の全幅で起きていた）。
  1240px以上は余白を詰めて番号付きの電話ボタンまで並べ、1041〜1239pxは電話をアイコンにし「資料ダウンロード」を「資料DL」と短縮する。
  ヘッダーに文字を足したら、1041〜1960pxではみ出し・折り返しが無いことを確認する。
- **追従ヘッダー**: `.site-header` は `position: fixed` で全ページ追従する。
  ラッパーの `[data-site-header]` が `--header-height` ぶんの高さを確保して
  本文の重なりを防ぐ。この高さは `app.js` が実測して設定するので、
  **ヘッダーの高さを変えてもCSSの数値を直す必要はない**。
  ⚠️ `position: sticky` に戻さない。ラッパーの高さがヘッダーと同じ(79px)ため、
  stickyだと79pxスクロールした時点で流れて**追従しなくなる**（2026-09-20に修正）。
- **フッター**: 背景は `--brand-navy-darkest`。ページごとに変えない。
- **ページ単位の要素指定**: `.service-page img` のようにページクラスと要素名だけで書く指定は、ヘッダー・フッターにも効く。
  ページ内だけに効かせるときは `.service-page :where(main) img` のように本文へ限定する（`:where()` で優先度は元のまま）。
  2026-09-28に、この指定でサービス内容・文面サンプル・活用シーンのロゴが4倍に拡大していたため修正した。
- **禁止**: `.home-page .site-header` のような**ページ別の上書きを足さない**。
  2026-09-17に、ヘッダー29件・フッター4件の上書きを削除して統一した。
  上書きがあると、ページ遷移のたびにロゴの形やCTAの色が変わる状態に戻る。
- 変更は必ず全ページに波及するため、`/`・`/service/`・`/faq/` の3ページで
  PC（1440px）とスマホ（390px・メニュー開閉）を確認する。

## 追従CTA（フローティングバー）

`app.js` が `.floating-cta` を生成し、**お問い合わせページ以外の全ページ**に出す。

- **導線**: 「資料ダウンロード」（白地＋枠。`/resources/#download`）、「無料で相談する」（青／`--brand-blue`）、「電話で相談」（濃紺）の3つ。
  ヘッダーCTAのオレンジと色を分け、画面下で主張しすぎないようにしている。
- **出す条件**: `max(画面高の60%, 420px)` を超えてスクロールしたら出る。
  ヒーローのCTAが見えている間は出さない（同じ導線を二重に見せないため）。
- **お問い合わせページでは出さない**。目の前のフォームと競合するため。
  判定は `path` が `/contact/` かどうかで行う。
- フッターの最下部リンクが隠れないよう、`body.has-floating-cta .site-footer` に
  バーの実測高に連動する下余白を確保している。
- `app.js` がヘッダーとバーの実測高をルートのCSS変数へ反映し、スクロール余白にも使う。
  Tab・Shift+Tabで選択中のリンクやFAQが固定要素に隠れる場合だけ、表示位置を補正する。
  固定ヘッダー内・CTA内の操作と、モバイルメニューのフォーカス制御は補正対象にしない。
- スマホ（768px以下）では「資料DL」「無料相談」と短縮して残りの横幅を等分し、電話は「電話」と短縮した幅固定のボタンにする。
  374px以下は「資料DL」「無料相談」のアイコンを外して3つを1行に収める。PCの電話ボタンは番号まで表示する。

## TOPデザイン

- PCは1440px前後を基準にし、共通コンテンツ幅は最大1180px、サービス工程セクションは最大1280px、役割分担セクションは最大1120pxとする。
- 見出しの書体は「書体（全ページ共通）」に従う。TOPだけ別の書体指定を作らない。
- TOPで使う写真・人物イラストの正本は `dist/assets/images/` に置く。見出し、説明、数値、ボタンなど判断に必要な情報は画像に含めずHTMLで表示する。
- 主要画像には固有の `alt`、`width`、`height` を指定し、ファーストビュー以外は遅延読み込みにする。
- 3つの工程（企業調査／送る理由・文章を設計／フォーム送信・管理）は1024px以下でも3列、特徴の4カードは1024px以下で2列にし、768px以下では各セクションを1列にする。スマートフォンではCTAを横幅いっぱいにし、縦書きコピーは非表示にする。
- ファーストビューの見出し（h1）は「客先接触面積の最大化を、最小工数で。」とし、直下に「月3万〜8万件の圧倒的な母数で新規開拓を支援します」と「1社1社カスタマイズの文章を制作して送信します」を表示する。PCの基本高さは620pxとし、画像周囲の余白とコピー量のバランスを取る。
- 特徴の4カードは、修正スライドの「企業ごとのカスタマイズ文章／月3万〜8万件の送信規模／運用・管理を丸ごとお任せ／低価格のコストパフォーマンス」とする。4つ目は業界最安値と言い切らず、範囲を限定した低価格と送信試行1件あたりの単価で示す。
- 新規開拓の課題セクション（「新規開拓が、日々の業務に埋もれている」）は2026-09-28に削除した。
- 事前確認の3カードには、プラン別の月間送信数と月額の比較図、架空文面のHTML抜粋、業種別イラストを表示する。900px以下では1列にし、比較内容を読める幅を確保する。比較図は料金ページの記載に合わせ、未確定の金額・件数を作らない。見出し・説明・リンクは画像にせずHTMLで残す。

## スマートフォンの表示・操作

- モバイル共通の調整は `dist/assets/style.css` 末尾の `Shared mobile experience` を正本とし、各ページのPC用スタイルより後に置く。同じメディア条件・同じセレクターの指定は一か所へまとめ、前半に上書き前の値を残さない。移動するときは、他のセレクターとの優先順位と、省略していない有効なプロパティも確認する。
- サービスのヒーローは本文と工程カードを通常の配置に置く。幅49%の本文と幅58%の絶対配置カードを組み合わせる旧方式や、その重なりを避ける補正は追加しない。
- 768px以下は本文16pxを基本とし、画面幅に応じた見出し、左右16〜20pxの余白、本文と重ならない画像配置にする。PC向けの改行やカードの固定高さを持ち込まない。
- 共通メニューは1040px以下で切り替える。資料・相談・電話を含む8つの導線を保ち、閉じる操作、Escapeキー、画面幅変更、ページ遷移後にスクロールロックを残さない。
- スマホのヘッダーは64px、相談リンク・メニューボタンは44px以上、本文の主要ボタンは52px以上を基準にする。ページ内リンク先がヘッダーに隠れない余白を確保する。
- 高さ480px以下の横画面では、ヘッダー内側の高さを56pxにし、追従CTAの上下余白を縮める。ヘッダーと追従CTAのボタンは44px以上、安全領域とフォーカス枠の余白を保つ。メニューの開始位置と高さは実測した `--header-height` に連動させる。
- 活用シーンの業種カードは900px以下で1列にし、見出しと本文の幅を確保する。
- 比較表と細かい管理画面画像は領域内で横スクロールさせる。横に続く場合だけ案内を出し、キーボードでも移動できる領域にする。料金比較表の左列は項目名として固定する。
- 文面サンプルはPC・スマホとも同じHTMLテキストで表示する。「架空サンプル」の表示を保ち、画面幅によって社名・商材・本文が変わらないようにする。
- 導入相談は幅820pxの1列で、電話相談の枠、フォームの順に表示する。スマホでは電話番号のボタンを横幅いっぱいにする。入力欄は16px以上とし、受付完了・送信失敗の表示も375・768・1280pxで崩れないことを確認する。
- モバイルではスクロール演出の表示待ちをせず本文を表示する。縦に長いグリッドが画面に入りきらなくても内容を隠さない。

- 返信数は、これまでの結果（50,000件の送信で約30件、約1,666件に1件）と、それを各プランの送信件数で単純換算した目安（約18・30・48件）を区別して書き、結果が変動し保証しない旨を添える。
- 「実績」という語は使わない。自社の数値は「これまでの結果」「返信件数」のように事実として書き、「実績とノウハウ」のような裏付けを示せない訴求はしない。
- 「業界最安値」「最安」など一番安いと言い切る表現は使わない。「文面作成から送信までを代行するサービスの中で低価格」のように、比較した範囲（代行サービスに限り、ツール型を含まない）を明示し、根拠となる比較を同じページに示す。1社ごとにAIで文面を作るツール（1通5円台）が存在するため、ツールを含めた「サービスの中で」という書き方はしない。

## 問い合わせと停止窓口

- 導入相談と、営業案内を受け取った企業からの送信停止依頼は別窓口にする。停止窓口へは、フッターの「送信停止・受信窓口」から案内する。
- 運営会社の問い合わせ先メールは `office@contentsx.jp`（`content-x.co.jp` は存在しないドメインで、メールが届かないため使わない）。運営会社ページ、導入相談フォームの失敗・受付完了の案内、送信停止窓口で同じアドレスを使う。
- 電話相談は `03-6261-0764`（ビズマンガと同じ番号）。導入相談ページ、共通ヘッダー、メニュー、追従CTAに `tel:` リンクで表示する。番号は `app.js` の `TEL` と導入相談ページの2か所で管理する。
- 導入相談フォームは `dist/assets/app.js` から **HubSpot（主）と Contents X CRM の受信箱（従）の両方へ送る**。BizManga・ContentsX・イチオシ採用と同じ構成。送信先・識別子・トークンの扱いは README の「外部連携」を正本とする。
  - 受付完了と失敗の判定は HubSpot の応答だけで行う。CRM へは埋め込みスクリプトの `BizcarteInbound.sendForm(form)` で写しを送るだけで、失敗しても画面にも HubSpot 送信にも影響させない（既存の問い合わせ受付を壊さないため）。
  - 成功したらフォームを隠し、受付完了と次の流れ（`[data-contact-complete]`）を表示する。
  - 失敗の案内は2種類に分ける。**HubSpot が 4xx を返したとき**（入力の検証で拒否＝届いていない）だけ、入力内容の確認と再送を促す。**通信断・時間切れ・5xx**（届いたか分からない）では「もう一度お試しください」と書かない。応答が取れなかっただけで届いている場合があり、再送で重複するため。どちらも `office@contentsx.jp` へのメールを案内する。
  - 完了・失敗の文言はHTMLに固定で置き、入力値を画面へ差し込まない。
  - 二重送信はボタンの無効化だけでなく、フォーム単位の送信中フラグで止める（Enterキーや `requestSubmit()` はボタンを経由しない）。
  - ハニーポット `#bfWebsite`（`name="website"`・`tabindex="-1"`）は画面外に置く。`display:none` にしない。値が入っていたら HubSpot へ送らず、画面には受付完了を出す（CRM の埋め込みスクリプトがこの形を自動で認識し、CRM 側で黙って捨てる）。
  - 入力の上限（会社名・氏名200字、詳しい内容5000字）は CRM 側の受付上限（会社名・氏名200字、本文10000字）より小さくしてある。
- フォームは `method="dialog"` のまま保ち、JavaScriptが動かなくてもHTTP送信に切り替わらない構造にする。ボタンは初期状態で無効化し、送信処理の登録後に有効化する。読み込み失敗時も使える運営会社フォームへのリンクを表示する。
- `/stop/`（送信停止窓口）は HubSpot にも CRM にもつながない。停止依頼を営業の問い合わせと混ぜないため。
- 停止依頼の処理期限と社内責任者は、正式公開前に決める。

## 資料ダウンロード

- 場所は `/resources/#download`（`dist/resources/index.html`）。ヘッダー・メニュー・追従CTA・フッター・各ページ末尾のCTAの「資料ダウンロード」はすべてここへ飛ぶ。トップのヒーローのCTA（料金を見る／無料で相談する）には足していない。
- PDFの正本は `dist/assets/docs/bizform-service-guide-202609.pdf`（営業資料 0926 版・29ページ）。元の49.3MBを、macOS標準のQuartzフィルタ（JPEG品質0.6）で画像を圧縮し、元からJPEGだった4枚は元のJPEGのまま戻して約11MBにした。見た目は全ページを画像にして元と比べて確認済み。資料を差し替えるときも10MB前後を目安にし、50MBを超えるファイルはコミットしない。
- **PDFへの直接リンクを、ナビ・本文などフォームを通らない場所に置かない**。PDFの場所はフォームの `data-download-url` にだけ書き、完了表示の「こちらからダウンロード」は送信後に `app.js` がリンク先を入れる。`robots.txt` で `/assets/docs/` をクロール対象から外している。静的ファイルなので、URLを知っている人は直接開ける（強い保護ではない）。
- 項目は会社名・お名前・メールアドレス（必須）、部署名・電話番号（任意）、プライバシーポリシーへの同意（必須）。**問い合わせ内容の欄は作らない**。ハニーポット `#bfDlWebsite` は導入相談と同じ形。
- `app.js` は入力チェックを通ったら、HubSpot へ写し → CRM へ写し（`BizcarteInbound.sendForm(form)`。フォームの `data-crm-form="download"` と `data-crm-document` で受信箱の「資料DL」の箱に入る）→ ダウンロード開始、の順に実行し、**どの応答も待たない**。HubSpot や CRM が落ちていてもダウンロードは止まらない。
- HubSpot へは導入相談と同じフォームに送り、本文欄（`message`）に「【資料ダウンロード】資料名」と電話番号を入れて資料DLだと分かるようにする。HubSpot は廃止予定のため、失敗してもコンソールに警告を出すだけにしている。
- 資料を差し替えたら、`data-crm-document` の資料名、ページの説明（ページ数・容量）、この節を同時に直す。

- 外部サービス・Cookieの説明は実装と一致させる。現状はGitHub Pagesによる配信と、HubSpot・当社CRMへ送る導入相談フォーム・資料ダウンロードのフォーム（2026-09-26・2026-09-28 に「6. 外部サービスの利用」へ反映）。**HubSpotのトラッキングコードは読み込んでいない**ため「10. Cookie・アクセス解析」は変えていない。トラッキングコードや解析ツールを入れるときは、先にこのポリシーを改定する。他サービスのポリシーから解析・広告の記載をそのまま転記しない。

## ソースの整形・整理

- 文字コードはUTF-8、改行はLF、HTML・CSS・JavaScriptのインデントはスペース2つとする。設定は `.editorconfig` を参照する。
- HTMLはセクション・カード・フォーム項目などの単位で改行する。日本語本文、インライン要素の前後の空白、意図した `br`、属性、要素の順序は維持する。
- HTML整形は `python scripts/format_html.py`、整形済みかの確認は `python scripts/format_html.py --check` で行う。整形と表示・文言の変更は分けてレビューする。
- CSSを削除するときはHTMLだけでなく、JavaScriptが生成する要素や操作後の状態も確認する。`:not()` 内で参照するクラスがなくても、そのルール自体は使用中の場合がある。
- CSSの整理ではブラウザ向けのフォールバック宣言を保ち、PC・スマホ・切替境界の表示とメニュー・FAQ・フォームの操作を確認する。
